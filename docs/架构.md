# 架构

## 两种形状与选择

### A. 单体 MenuBarController（未采用）

SwiftUI/`NSStatusItem` 直接创建 URLSession、解析 JSON、管理 Timer。

- 优点：文件少
- 缺点：UI 拥有连接状态；Linux 无法测；Provider 边界易渗漏

### B. Core 库 + 薄 App 壳（采用）

```
Apps/AIQuoty          → MenuBarExtra / Settings / Dashboard（仅 macOS）
Sources/AIQuotyCore   → 模型、解析、Provider、RefreshCoordinator、钥匙串协议
Sources/AIQuotyCLI    → 无 UI 状态打印（Linux/macOS）
```

**单一所有权：** 只有 `RefreshCoordinator` actor 写入账号快照、错误、退避与 demo 开关。Provider 无共享可变状态；失败时对**该账号**标记 stale，不波及其他账号。

## Provider 边界

每个 `QuotaProvider`：

1. 声明 `ProviderDescriptor`（实现状态、鉴权方式、指标种类）
2. `configuredAccounts()` 只做存在性探测
3. `fetch` 返回 `AccountSnapshot[]`，数字必须带 `MetricKind` + `MetricPrecision` + `SourceAttribution`

禁止：

- 用本地 token 日志推断订阅剩余
- 跨服务求和配额窗口
- 把缺失重置显示成「已重置」或 0%
- 在 UserDefaults 存密钥

## 刷新与退避

- 默认间隔 300s（设置可调）
- HTTP 429 → `rateLimited` + 指数/响应头退避，保留上次成功窗口并标 `stale`
- 401/403 → `authRequired`
- 未配置 Provider 静默跳过（不在实时 UI 填假数）

## 演示模式

显式开关；使用 `DemoFixtures` 合成 JSON。实时模式禁止注入 mock。
